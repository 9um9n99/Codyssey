# 조각조각 — 프론트엔드 설명서

Codyssey "AI 웹 개발" 미션 프로젝트. 막막한 목표를 오이 조각처럼 쪼개서 실행하게 돕고,
완성하면 오이 요리로 기록되는 서비스. 이 문서는 현재까지 만들어진 프론트엔드 전체를
페이지 단위로 정리한 것으로, 특정 부분을 수정 요청할 때 "몇 번 페이지의 어느 항목"
식으로 짚어 말하는 용도로 쓰면 됩니다.

---

## 0. 전체 구조

```
index.html      메인 (소개 + 서비스 안내)
cutting.html    오이 썰기 (목표 입력 → AI 조각내기, 입력 전용)
calendar.html   캘린더 (진행 중인 모든 목표를 달력 + 체크리스트로 관리)
record.html     오늘의 요리판 (완성 기록 + 요리 도감)

css/style.css   전체 공통 스타일
js/main.js      전 페이지 공통 데이터/함수 (요리 도감 데이터, ID 생성기)
js/cutting.js   오이 썰기 페이지 로직
js/calendar.js  캘린더 페이지 로직
js/record.js    요리판 페이지 로직
images/         이라스토야 일러스트 7종
api/chop.py     (비어있음, 6단계에서 Claude API 연동 예정)
```

**네비게이션 순서** (모든 페이지 공통, 헤더 상단): 메인 → 오이 썰기 → 캘린더 → 오늘의 요리판

**색상/폰트 토큰** (`css/style.css` 상단 `:root`):
- 배경 `#F4F8EC`, 카드 배경 `#FFFDF7`, 메인 그린 `#3F6E44`, 포인트 레드 `#E2673B`, 포인트 옐로 `#E8A93E`, 텍스트 `#24301E`
- 제목 폰트: Gaegu(손글씨풍) / 본문 폰트: Pretendard

**데이터 저장 방식** (모두 브라우저 localStorage, 서버 없음):
| 키 | 내용 |
|---|---|
| `jogak-active-plans` | 진행 중인 목표들의 배열 (여러 개 동시 가능) |
| `jogak-records` | 완성한 목표들의 배열 (요리판 + 도감의 원천 데이터) |

## 1. 메인 (`index.html`)

첫인상과 서비스 소개를 담당하는 랜딩 페이지. 위에서 아래로 5개 구역.

### 1-1. 히어로
- 오이 두 개 이미지 (`kyuuri_cucumber.png`)
- 노란 배지: "막막한 목표가 있으신가요?"
- 제목: **"한 덩이 목표를 조각조각 썰어드려요"**
- 설명: `"포트폴리오 만들기", "이사 준비" 같은 막막한 목표를 입력하면, AI 오이 손질사가 실행 가능한 단계로 잘게 썰어줘요.`
- 버튼 "지금 오이 썰어보기 →" → `cutting.html`로 이동
- 그 아래 오이 단면 이미지(`cut_vegetable_cucumber.png`)가 **계속 빙글빙글 회전** (5초 주기)

### 1-2. 소개 드롭다운 (`<details>` 아코디언, 기본은 접혀있음)
- 토글 문구: "🥒 조각조각, 어떤 서비스인지 살펴보기"
- 펼치면 레시피 카드 느낌의 이중 테두리 박스가 나오고, 안에 4블록:
  1. **왜 만들었나요** — 서비스 취지 설명 텍스트
  2. **재료 (필요한 것)** — 목표 / 기한 / 의지, 3개 리스트
  3. **조리법 (이용 방법)** — 오이 썰기 입력 → AI 분석 → 체크 → 요리판 기록, 4단계 리스트
  4. **완성되는 요리들** — 난이도별 요리 16종 전체 목록(아래 4-3 참고)
  - 맨 아래 버튼 "첫 오이 썰어보러 가기 →" → `cutting.html`

### 1-3. 어떻게 쓰나요 (3단계 카드, 고정 노출)
1조각 "목표를 적어요" / 2조각 "기한을 정해요" / 3조각 "조각을 받아요" — 각각 한 줄 설명 포함

### 1-4. 요리 도감 미리보기 (카드 하나)
- 라벨 "요리 도감 미리보기"
- 제목 "완성한 목표는 요리로 기록돼요"
- 버튼 "요리 도감 구경하기" → `record.html`

### 1-5. 구분선
오이 조각 모양 점 5개가 반복되는 시그니처 디바이더 (`.cucumber-divider`)가 섹션들 사이사이에 들어감

**이 페이지는 JS 로직이 따로 없음** (main.js만 로드, 상호작용은 아코디언 열고 닫기가 전부)

## 2. 오이 썰기 (`cutting.html`)

**역할이 명확히 하나뿐인 입력 전용 페이지.** 여기서 결과를 보여주지 않고, 완료되면
**`calendar.html`로 자동 이동**함 (진행 상황은 전부 캘린더 페이지에서 관리).

### 2-1. 입력 폼
- 제목 "어떤 목표를 썰어드릴까요?"
- 부제 "여러 목표를 동시에 진행할 수도 있어요. 완료되면 캘린더로 이동해요."
- textarea "목표 (통오이)" — placeholder: "예: 리디자인 포트폴리오 만들기"
  - 비어있는 채로 제출하면 에러 문구 노출: "목표를 입력해주세요. 오이가 없으면 썰 수 없어요 🥒"
- 기한 입력 — 숫자 스테퍼(−/+ 버튼), 기본값 7일, 최소 1 / 최대 90
  - 버튼을 **꾹 누르고 있으면** 0.4초 후부터 0.08초 간격으로 빠르게 증가/감소
  - 브라우저 기본 숫자 스피너(위아래 화살표)는 CSS로 숨김 처리됨
- 제출 버튼 "오이 썰어주세요 🔪"

### 2-2. 로딩 상태 (제출 후 1.5초간 표시)
- 오이 손질 손 이미지(`cooking04_usugiri.png`)가 살짝 흔들리는 애니메이션
- 문구: "오이 손질사가 목표를 살펴보는 중..."

### 2-3. 오류 상태
- 낙담한 요리사 이미지(`fusagikomu_chef_woman.png`)
- 오류 메시지 2종:
  - 일반 오류: "오이 손질사가 잠시 자리를 비웠어요. 잠시 후 다시 시도해주세요."
  - 타임아웃: "응답이 너무 오래 걸리고 있어요. 잠시 후 다시 시도해주세요."
- "다시 시도하기" 버튼 (마지막 입력값으로 재시도)

### 2-4. 성공 시
새 계획을 `jogak-active-plans`에 저장하고 → **`calendar.html`로 즉시 이동**

**⚠️ 현재는 목업**: `requestChopping()` 함수가 실제 AI 대신 `목표 — N단계 (예시 조각)`처럼
기계적으로 생성함. 6단계(백엔드 연동)에서 `api/chop.py` + Claude API로 교체 예정.

## 3. 캘린더 (`calendar.html`)

**진행 중인 모든 목표를 관리하는 허브.** 위: 달력, 아래: 목표별 체크리스트 카드.

### 3-1. 진행 중인 게 하나도 없을 때
- 요리사 이미지(`kid_job_girl_chef.png`)
- "아직 진행 중인 오이가 없어요."
- 버튼 "오이 썰러 가기 →" → `cutting.html`

### 3-2. 달력 (진행 중인 게 1개 이상일 때)
- 제목 "이번 달, 오이가 이어지는 길"
- 부제: "N개의 목표가 진행 중이에요"
- 가장 이른 시작일이 속한 달의 월간 달력(일~토, 6주 그리드)
- **목표(계획)마다 다른 색깔**의 막대가 해당 기간의 날짜 칸에 이어져서 표시됨
  - 막대는 시작/끝 지점에서 둥글게 처리되어 "이어지는" 느낌을 줌
  - 각 목표의 시작일 칸에는 목표 이름이 짧게(6자+…) 표시됨
  - 색상 팔레트는 10가지 순환 (`PLAN_COLORS`)
- 하단 범례: 색상 점 + "목표명 (완료조각/전체조각)"

### 3-3. 요약 문구
"N개의 목표 진행 중 · 총 X/Y조각 완료" — 모든 진행 중 계획을 합산

### 3-4. 진행 중인 오이 카드 (계획 하나당 카드 하나)
각 카드 안에 포함된 것:
- 색상 점 + 목표 이름 + "N일 목표" 태그
- 조각 체크리스트 — 각 줄: 체크박스 + "N조각 · 제목" + **기한(일수) 수정 가능한 입력창**
  - 기한을 바꾸면 그 계획의 이후 조각들 날짜가 자동 재계산되어 달력에도 즉시 반영됨
- 진행률 바 + "N조각 중 M조각 완성" 라벨
- 전부 체크하면: 완성 배너 노출 — "오늘의 요리 완성! [요리명] 🎉" + 요리사 이미지(`job_chef_woman.png`) + 버튼 "요리판에서 확인하기 →"
  - 이 순간 자동으로 `jogak-records`에 저장되고 진행 목록에서 제거됨
- "이 오이 그만 썰기" 버튼 — 그 목표만 진행 목록에서 삭제 (기록에는 안 남음)

**호환성 참고**: 예전 버전(계획을 1개만 관리하던 방식, `jogak-active-plan` 단수 키)으로
저장된 데이터가 있으면 페이지 로드 시 자동으로 새 배열 방식으로 변환됨.

## 4. 오늘의 요리판 (`record.html`)

완성 기록과 도감을 둘 다 보여주는 페이지. 위: 완성한 기록 리스트, 아래: 요리 도감.

### 4-1. 완성 기록이 하나도 없을 때
- 오이 먹는 아이 이미지(`marukajiri_kyuuri_girl.png`)
- "아직 완성한 요리가 없어요."
- 버튼 "첫 오이 썰러 가기 →"

### 4-2. 완성 기록 리스트 (최신순 카드)
각 카드: 오이무침 접시 아이콘(`food_tsukemono_kyuuri.png`) + 요리명 / 목표 텍스트 / 태그(조각 수·기한·완성일)

**카드를 클릭하면** 모달이 뜨고, 그 목표를 완성했을 때의 **조각 체크리스트**가 다시 나옴
(체크박스 상태를 여기서도 토글 가능 — 바꾸면 바로 저장됨)

### 4-3. 요리 도감 (난이도 4단계 × 요리 4종 = 총 16종)
| 난이도 | 요리 4종 |
|---|---|
| 2~3조각 (가볍고 빠른 목표) | 오이무침 · 오이냉채 · 오이피클 · 오이초절임 |
| 4~6조각 (손이 조금 가는 목표) | 오이소박이 · 오이볶음 · 오이잡채 · 오이월과채 |
| 7~9조각 (정성이 필요한 목표) | 오이냉국 · 오이소면 · 오이김치 · 오이비빔국수 |
| 10조각 이상 (긴 호흡의 목표) | 오이지 · 오이장아찌 · 오이고추장무침 · 오이된장박이 |

- 상단에 "N / 16종 발견" 진행률
- 아직 못 만든 요리는 `❓`와 "？？？"로 잠겨있고 클릭 불가
- 만든 요리는 이미지 아이콘 + 요리명 + "N번 완성"으로 표시, **클릭하면** 그 요리를
  만들었던 모든 기록이 모달에 히스토리로 쭉 나열됨 (이쪽은 체크박스 없이 목록만)

**요리 선택 로직** (완성 순간에 결정, `js/main.js`의 `pickDish()`):
같은 난이도 안에서 **아직 도감에 없는 요리를 우선으로 랜덤** 선택. 그 난이도를 이미
다 모았으면 그 난이도 안에서 랜덤. **16종을 전부 모았으면** 완전 랜덤으로 전환.
