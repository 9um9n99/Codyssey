# AI 도구 사용 기록

조각조각은 **서비스 안의 AI 기능**과 **개발 과정에서 쓴 AI 도구** 두 가지로 AI를 사용했습니다.

## 1. 서비스 안의 AI 기능
| 항목 | 내용 |
| --- | --- |
| 하는 일 | 사용자가 입력한 목표·기한(·첨부)을 읽고 실행 가능한 단계 목록으로 나눔 |
| 모델 | `claude-sonnet-4` (Codyssey 공개 API 콘솔, Anthropic 호환) |
| 호출 위치 | 서버리스 함수 `api/chop.py` (키는 서버 환경 변수에만 저장) |
| 입력 / 출력 | `{ goal, days, attachments }` → `[{"title": "..."}]` 순수 JSON |
| 프롬프트 설계 | 목표 성격 판단 → 논리 순서 → "구체적인 행동 하나"로 작성 → 기한별 단계 수 규칙 → JSON만 출력 |

## 2. 개발 과정에서 쓴 AI 도구 (Claude)
기획과 판단은 직접 하고, 구현·점검·문서 작성에 AI를 활용했습니다.

| 단계 | AI에게 시킨 일 | 직접 한 일 / 결정한 것 |
| --- | --- | --- |
| 기획 | 서비스 아이디어를 기능으로 구체화, 화면 구성 제안 | 콘셉트(오이·요리 은유), 3개 화면 구성, 우선순위는 목표 단위로만 두기 |
| 구현 | HTML/CSS/JS와 Python 서버 함수 작성, 파일·PDF 첨부, 편집 기능 | 요구사항 지시, 화면을 보며 수정 요청 |
| 디자인 | 색·글자 위계·간격 정리, 모바일 배치 | 레시피북 표지 이미지 선정, 방향 결정(반원 오이 헤더 등), 마음에 안 드는 안 거절 |
| 점검 | 처음 쓰는 사용자 입장에서 시나리오를 돌려 허점 찾기 | 발견된 문제의 수정 여부 결정 |
| 배포 | GitHub 푸시와 Vercel 설정 순서 안내 | 직접 명령 실행, 환경 변수 등록 |
| 문서 | README·기획서·설명서 초안 | 내용 확인과 최종 반영 |

### 점검에서 AI와 함께 찾아 고친 문제 (예)
- 기한 칸에 0·음수·91일 이상이 그대로 통과 → 1~90일로 자동 보정
- AI가 빈 응답·제목 없는 조각을 주면 빈 계획이 생김 → 걸러내고 오류 안내
- 쓰지 않고 나간 결과가 조리하기에 중복으로 남음 → "요리하러 가기"를 눌러야 저장
- 저장 데이터가 깨지면 전체 화면이 멈춤 → 깨진 데이터를 무시하고 열기

### 배운 점
- AI에게 "처음 쓰는 사람처럼 써보고 허점을 찾아줘"라고 시키면 직접 놓치는 예외 입력을 많이 발견함.
- 디자인은 한 번에 맡기기보다 화면을 보고 "여기가 못생겼다"처럼 구체적으로 짚어야 결과가 좋았음.
- API 키처럼 민감한 값은 AI와의 대화에 붙여넣지 않고 `.env`·Vercel 환경 변수로만 다룸.
