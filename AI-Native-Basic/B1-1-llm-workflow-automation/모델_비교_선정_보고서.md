# 모델 비교·선정 보고서

## 1. 비교 목적

디자인 리뷰 미팅 요약이라는 업무 과업에 대해, 3종 이상의 LLM(GPT-5.6, Gemini 3.1 Pro, Claude Sonnet 5)에 동일한 입력을 투입하여 결과를 비교하고, "느낌"이 아닌 평가 축과 근거를 기준으로 실제 업무에 사용할 모델을 선정한다.

**타겟 사용자**: 디자인 리뷰에 참석한 프로덕트 디자이너 본인 (회의 직후 셀프 정리용)
**입력 데이터 형태**: 가상의 회의 녹음 스크립트(텍스트)
**출력 규격**: 아래 8항목
1. 회의 날짜 / 리뷰 차수
2. 참석자
3. 리뷰 대상 (어떤 화면/시안)
4. 전체 디자인 상태 (승인 / 부분 수정 필요 / 재작업 필요)
5. 피드백별 반영 여부 (반영 확정 / 반려 / 추가 논의 필요)
6. Action Items (담당자·기한)
7. 이견 / 미합의 지점
8. 다음 리뷰 일정

**입력 템플릿**:
```
[회의 유형] 디자인 리뷰
[리뷰 차수]
[리뷰 대상 화면]
[참석자]
[스크립트/메모 원문]
[특이사항] (선택)
```

---

## 2. 비교에 사용한 동일 입력

세 모델 모두에 아래와 동일한 프롬프트(지시문 + 8항목 형식 + 규칙 3가지 + 회의 스크립트 전문)를 각각 새 대화창에서 1회씩, 총 2회(재실행 포함) 투입했다.

- 전체 프롬프트 원문: `공통_테스트_프롬프트.md`
- 회의 스크립트 원본(정답 대조용 메모 포함): `디자인리뷰_스크립트_원본.md`

스크립트에는 의도적으로 4가지 검증 장치를 심어두었다.
- 화자가 불분명한 발언 구간 1곳
- 논의는 됐으나 결론이 나지 않은 안건(쿠폰 중복 적용 정책) 1곳
- 담당자·기한이 명시되지 않은 Action Item
- 다음 리뷰 일정에 대한 구체적 날짜 언급 없음

### 재현성 기록

| 항목 | GPT-5.6 | Gemini 3.1 Pro | Claude Sonnet 5 |
|---|---|---|---|
| 모델명 | GPT-5.6 (Thinking) | Gemini 3.1 Pro | Claude Sonnet 5 |
| 요금제 | 유료 | 유료 | 유료 |
| 사용 채널 | 웹 | 웹 | 웹 |
| 사용 날짜 | 2026-08-15 | 2026-08-15 | 2026-08-15 |
| 주요 설정 | 기본값 | 기본값 | 기본값 |
| 무료 버전 제한사항 | 해당 없음 (유료 사용) | 해당 없음 (유료 사용) | 해당 없음 (유료 사용) |

## 3. 평가 축 (점수표)

| 평가 축 | 정의 |
|---|---|
| ① 정확성 | 스크립트에 없는 사실을 지어내지 않았는가 |
| ② 형식 준수 | 8항목을 빠짐없이, 정해진 순서로 냈는가 |
| ③ 모호함 처리 | 불확실한 지점(화자 불명, 미합의 등)을 숨기지 않고 표시했는가 |
| ④ 어조·가독성 | 불필요한 인사말·군더더기 없이 담백하게, 실무 문서 톤으로 나왔는가 |

※ ①③은 프롬프트 내 "지어내지 마라", "화자 불명 표시" 등의 명시적 규칙 준수 여부를 함께 측정한다.

### 점수표 (1차 실행 기준, 5점 만점)

| 평가 축 | GPT-5.6 | Gemini 3.1 Pro | Claude Sonnet 5 |
|---|---|---|---|
| ① 정확성 | 4 | 5 | 5 |
| ② 형식 준수 | 5 | 5 | 5 |
| ③ 모호함 처리 | 3 | 5 | 5 |
| ④ 어조·가독성 | 4 | 4 | 5 |
| **합계** | **16** | **19** | **20** |

### 참고: 일관성 재실행 결과 (동일 프롬프트 2회 투입)

형식(8항목 구조, 분류 카테고리)은 3개 모델 모두 1·2차 동일하게 재현했다. 다만 세부 판단에서는 차이가 있었다.
- GPT-5.6: 애니메이션 수정 건의 반영 여부 분류가 1차("반영 확정")와 2차("추가 논의 필요")에서 상반되게 나옴
- Claude Sonnet 5: Action Item 담당자 표기 방식이 1차("미정, 추정 근거 명시")와 2차("명확히 배정")에서 달라짐
- Gemini 3.1 Pro: 구조·분류·담당자 배정 방식 모두 1·2차 동일

이 차이는 최종 점수표(어조·가독성 축)에는 반영하지 않았으며, 참고 자료로 남긴다.

## 4. 모델별 결과 요약

**GPT-5.6**
8항목 형식은 정확히 지켰으나, 스크립트에 없는 수준까지 Action Item을 세분화하여(예: 애니메이션 검토를 별도 항목으로 분리하며 동일한 담당자·기한을 반복 부여) 실제보다 확정된 것처럼 보이게 하는 경향이 있었다. 화자 불명 발언은 이름을 지어내지는 않았으나, "화자 불명"이라는 표시 없이 Action Item에 조용히 흡수시켰다.

**Gemini 3.1 Pro**
화자 불명 표기, 미합의 지점 처리 모두 정확했고 Action Item도 스크립트 원문에 가깝게 포괄적으로 정리했다. 다만 결과물 서두에 "제공해주신 회의 스크립트를 바탕으로 요약한 디자인 리뷰 회의록입니다."라는 대화체 인사말이 남아, 실무 문서로 그대로 쓰려면 한 줄 삭제가 필요했다.

**Claude Sonnet 5**
화자 불명·미합의 지점을 정확히 표시했고, 판단 근거(반영 여부, 모호함 처리)마다 스크립트 원문을 직접 인용해 왜 그렇게 분류했는지 확인할 수 있게 남겼다. 인사말 없이 바로 본문으로 시작해 형식상 손볼 곳이 없었다.

---

## 5. 최종 선정 근거

4개 평가 축(정확성, 형식 준수, 모호함 처리, 어조·가독성) 비교 결과, Claude Sonnet 5가 20점(만점 20점)으로 세 모델 중 가장 높은 점수를 받아 이번 업무 과업(디자인 리뷰 미팅 요약)에 최종 선정했다.

Claude와 Gemini는 정확성·형식 준수·모호함 처리 3개 축에서 나란히 만점으로 동점을 기록해, 핵심 판단 능력 자체는 두 모델이 대등했다. 승부는 ④ 어조·가독성에서 갈렸는데, Gemini는 챗봇 대화체 인사말이 결과물 서두에 남아 실무 문서로 바로 쓰려면 한 줄을 삭제해야 했던 반면, Claude는 인사말 없이 바로 본문으로 시작해 손댈 곳 없이 팀에 공유할 수 있는 형태였다.

여기에 더해 Claude는 판단(반영 여부, 모호함 처리)마다 스크립트 원문을 직접 인용해 왜 그렇게 분류했는지 검증 가능하게 남긴 반면, Gemini는 결론만 제시해 근거를 추적하기 어려웠다. 이는 점수화되지는 않았지만, 사람이 결과를 다시 확인할 때 원문을 일일이 대조할 필요를 줄여준다.

GPT-5.6은 담당자·기한을 스크립트에 없는 수준까지 세분화해 확정처럼 보이게 하는 경향(정확성 감점)과 화자 불명 구간을 표시 없이 조용히 흡수하는 처리(모호함 처리 감점)로, 세 모델 중 가장 낮은 점수를 받아 이번 업무에는 부적합하다고 판단했다.
