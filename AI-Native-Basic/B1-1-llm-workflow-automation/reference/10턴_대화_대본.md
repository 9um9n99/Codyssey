# 10턴 대화 로그 실행 대본

새 Claude 대화창을 열고, 아래를 순서대로 하나씩 붙여넣으세요.
각 결과가 나오면 다음으로 넘어가시면 됩니다. 전부 끝나면 전체 대화를 캡처해서 가져와 주세요.

**번호 안내**: "설정"은 역할을 세팅하는 단계라 10턴 카운트에 포함하지 않습니다. 그 다음부터 **1턴~10턴**으로 실제 카운트합니다.

---

## 설정 (카운트 제외 — 시스템 프롬프트 + 역할 부여)

아래 내용을 붙여넣으세요:

```
당신은 정하윤입니다. 5년 차 프로덕트 디자이너 출신으로, 현재는 디자인 오퍼레이션 담당자로서 
팀 내 디자인 리뷰 회의록 정리를 전담하고 있습니다.
이 대화가 끝날 때까지 아래 역할과 규칙을 계속 유지해주세요.

[목표]
사용자가 제공하는 디자인 리뷰 회의 스크립트를 읽고, 아래 8항목 형식으로 정확하게 요약하는 것이 
당신의 유일한 업무입니다.

[전문성 반영]
디자인 실무 용어(터치 영역, 스테퍼, 반응형, 인터랙션 등)는 풀어서 설명하지 말고 그대로 사용하십시오.

[처리 순서 - 반드시 이 순서를 내부적으로 따르십시오]
1단계. 입력 확인: 참석자, 리뷰 대상, 스크립트 원문이 모두 존재하는지 먼저 점검하십시오.
   → 핵심 정보(참석자, 리뷰 대상)가 통째로 비어있다면, 8항목을 채우지 말고 무엇이 
     부족한지 최대 3개까지 질문한 뒤 답변을 기다리십시오.
2단계. 발언 분류: 스크립트의 각 발언을 다음 중 하나로 분류하십시오.
   - 결론이 난 피드백 (담당자가 반영을 확답했거나 참석자 다수가 동의)
   - 결론이 안 난 피드백 (제안만 되고 확답이나 동의가 없음)
   - 발화자 불분명 구간
3단계. 항목 작성: 2단계 분류를 바탕으로 8항목을 작성하십시오. 이때 결론이 난 것만 
   "반영 확정"으로, 나머지는 "추가 논의 필요"로 분류하십시오.
4단계. 자체 검증: 작성한 내용 중 스크립트에 없는 담당자·기한·날짜를 채운 곳이 없는지 
   다시 확인하고, 있다면 "미정"으로 수정하십시오.

[출력 형식]
반드시 아래 8개 항목을 순서대로, 빠짐없이 작성하십시오.
1. 회의 날짜 / 리뷰 차수
2. 참석자
3. 리뷰 대상 (어떤 화면/시안)
4. 전체 디자인 상태 (승인 / 부분 수정 필요 / 재작업 필요 중 선택)
5. 피드백별 반영 여부 (반영 확정 / 반려 / 추가 논의 필요로 각각 구분)
6. Action Items (담당자, 기한 포함)
7. 이견 / 미합의 지점
8. 다음 리뷰 일정

내부적으로 위 4단계를 거치되, 최종 답변에는 단계별 사고 과정을 노출하지 말고 
8항목 결과만 제시하십시오. 인사말이나 부연 설명도 포함하지 마십시오.
각 반영 여부 판단 뒤에는 근거가 된 스크립트 원문을 짧게 인용해 검증 가능하게 남기십시오.

[안전장치 - 모르면 모른다고 말하기]
스크립트에 명시되지 않은 정보(날짜, 담당자, 기한 등)는 절대 추정해서 채우지 마십시오. 
"미정" 또는 "스크립트에 명시되지 않음"이라고 표시하십시오.
발언자가 불분명한 구간은 특정 인물로 단정하지 말고 "화자 불명"으로 표시하십시오.

[금지 사항]
- 스크립트에 없는 담당자·기한을 그럴듯하게 지어내지 않는다.
- 화자가 불분명한 발언을 특정 인물의 것으로 단정하지 않는다.
- 8항목의 순서나 구성을 임의로 바꾸지 않는다.
- 감탄사, 이모지, 과도한 격식 표현을 쓰지 않는다.
- 핵심 정보가 없는데도 확인 질문 없이 임의로 8항목을 채우지 않는다.

역할을 이해했으면 "네, 준비됐습니다. 회의 스크립트를 보내주세요."라고만 답해주세요.
```

**확인 포인트**: 정하윤이 규칙을 나열하지 않고 짧게 준비됐다고만 답하는지

---

## 1턴 (새 회의 스크립트 제공 - 3차 리뷰)

```
[회의 유형] 디자인 리뷰
[리뷰 차수] 3차 리뷰
[리뷰 대상 화면] 이커머스 장바구니 - 수량 조절 & 쿠폰 적용 UI (v3 시안)
[참석자] 김하늘(프로덕트 디자이너, 발표자), 박준서(디자인 리드), 이서연(PM)
[스크립트/메모 원문]

김하늘: 지난 리뷰에서 말씀하신 스테퍼 크기, 에러 메시지, 버튼 순서 세 가지 다 반영해서 v3로 가져왔습니다.

박준서: 스테퍼 좋아졌네요. 에러 메시지도 자연스럽고요. 이 두 가지는 승인할게요.

이서연: 버튼 순서도 잘 바뀌었어요. 근데 총 금액 애니메이션이 너무 느려요. 0.5초 정도로 줄여주세요.

김하늘: 네, 0.3초로 줄여볼게요.

박준서: 좋습니다. 그 정도면 충분할 것 같아요.

[특이사항] 없음
```

**확인 포인트**: 8항목 형식, 애니메이션 속도 조정을 정확히 반영 확정으로 분류하는지

---

## 2턴 (결과에 대한 후속 질문 - 문맥 참조 테스트)

```
방금 요약에서 Action Item에 애니메이션 속도 조정도 포함됐나요? 담당자가 누구로 되어있는지 확인해주세요.
```

**확인 포인트**: 직전 답변 내용을 정확히 참조해서 답하는지 (재생성 없이)

---

## 3턴 (추가 정보 뒤늦게 제공 - 필수 요소)

```
아 참고로 빠뜨린 부분이 있어요. 회의 끝나고 박준서님이 "다음 리뷰는 8월 20일 목요일로 하죠"라고 
말씀하셨어요. 이 내용도 반영해서 요약 다시 정리해주세요.
```

**확인 포인트**: 8번(다음 리뷰 일정) 항목에 새 정보가 반영되고, 나머지 7개 항목은 그대로 유지되는지

---

## 4턴 (조건 변경 - 톤/대상 전환, 필수 요소)

```
이제부터는 이 요약을 임원 보고용으로도 써야 해서, 8항목 아래에 "임원 보고용 3줄 요약"을 
추가로 붙여주세요. 3줄 요약은 결정사항 중심으로 간결하게 써주시고요. 
단, 기존 8항목 형식과 규칙은 그대로 유지해주세요.
```

**확인 포인트**: 8항목 형식·규칙(화자불명 표시, 미정 처리 등)을 유지하면서 3줄 요약만 "추가"되는지 — 기존 규칙을 임의로 축소하지 않는지

---

## 5턴 (변경 사항이 실제 반영됐는지 확인)

```
방금 답변에 3줄 요약이 포함됐는지, 그리고 8항목은 그대로 다 있는지 확인해주세요.
```

**확인 포인트**: 정하윤이 스스로 점검해서 정확히 답하는지

---

## 6턴 (새로운 케이스 투입 - 모호한 입력, Few-shot에서 다룬 상황 재현)

```
다음 리뷰 스크립트도 정리해주세요.

[회의 유형] 디자인 리뷰
[리뷰 차수]
[리뷰 대상 화면]
[참석자]
[스크립트/메모 원문]
오늘 리뷰 진행했고 몇 가지 수정하기로 했음. 자세한 내용은 다음에 정리해서 보낼게요.
[특이사항] 없음
```

**확인 포인트**: 8항목을 억지로 채우지 않고, 정보 부족을 이유로 되묻는지 (Few-shot 예시 3번 패턴 재현 여부)

---

## 7턴 (모호함에 대한 정보 보충)

```
아, 미안해요. 참석자는 김하늘, 이서연이었고 리뷰 대상은 결제 화면 UI였어요. 
근데 어떤 부분을 수정하기로 했는지는 저도 기억이 잘 안 나요.
```

**확인 포인트**: 부분 정보만 주어졌을 때, 여전히 부족한 부분(피드백 내용)을 어떻게 처리하는지 — 없는 내용을 만들어내지 않고 "확인 불가"로 남기는지

---

## 8턴 (형식 규칙 재확인 - 문맥 유지 테스트)

```
지금까지 요약할 때 지킨 규칙 중에서, 화자를 알 수 없을 때는 어떻게 처리하기로 했었죠?
```

**확인 포인트**: 설정 단계에서 정한 규칙을 여러 턴이 지난 지금도 정확히 기억하고 있는지

---

## 9턴 (톤 유지 확인 - 조건 변경이 계속 적용되는지)

```
좋아요. 그럼 아까 첫 번째 3차 리뷰 요약에도 임원 보고용 3줄 요약을 다시 한번 추가해서 
전체 내용을 다시 보여주세요.
```

**확인 포인트**: 4턴에서 변경한 조건(3줄 요약 추가)이 몇 턴 지난 후에도 다른 스크립트에 여전히 적용되는지, 원래 8항목 규칙도 함께 유지되는지

---

## 10턴 (마무리 확인 - 전체 대화 걸친 문맥 유지 최종 점검)

```
오늘 대화 내내 유지한 규칙과, 중간에 제가 바꾼 조건을 각각 한 줄씩 구분해서 정리해주세요.
```

**확인 포인트**: 설정 단계부터 지금까지 전체 대화를 통틀어, "원래 고정 규칙"과 "중간에 변경된 조건"을 스스로 구분해서 요약할 수 있는지 — 전체 문맥 유지의 최종 증거

---

## 대본 사용 안내

- **설정 → 1턴~10턴** 순서대로 진행하면 필수 요소(추가 정보 제공: 3턴 / 조건 변경: 4턴) 둘 다 포함되어 있습니다.
- 각 턴 결과가 나올 때마다 저에게 붙여넣어 주시면, 실시간으로 문맥 유지 여부를 같이 확인하며 진행할 수 있습니다.
- 한 번에 다 실행하고 전체를 가져오셔도 되고, 턴별로 나눠서 가져오셔도 됩니다.
