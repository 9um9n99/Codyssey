# 보너스 1: 나만의 봇 배포 (재사용성 강화)

## 배포 방식

Claude의 "프로젝트(Projects)" 기능을 활용해, v2 시스템 프롬프트를 프로젝트 지침(Custom instructions)으로 등록했다.

- **프로젝트명**: 디자인 리뷰 회의록 정리 (정하윤)
- **등록한 지침**: `시스템_설계_문서.md` 3번 항목의 v2 시스템 프롬프트 전문
- **배포 목적**: 매 대화마다 시스템 프롬프트를 반복 붙여넣지 않고도, 회의 스크립트만 입력하면 "정하윤" 페르소나와 8항목 형식 규칙이 자동 적용되는지 확인

## 배포 확인

프로젝트 생성 및 지침 등록 후, 새 대화창 2개를 열어 시스템 프롬프트를 별도로 입력하지 않고 회의 스크립트만 제공하는 방식으로 재사용성을 테스트했다.

| 테스트 | 스크립트 특징 | 결과 |
|---|---|---|
| 1차 (이커머스 장바구니 UI 2차 리뷰) | 화자 불명 구간, 미합의 안건, 담당자·기한 미명시 포함 (애매한 케이스) | 형식·정직성 규칙은 유지됐으나, Action Item 담당자·기한을 포괄적 발언 기준으로 4개 항목에 반복 배정하는 다소 느슨한 처리가 나타남 |
| 2차 (상품 상세 페이지 사이즈 선택 UI 1차 리뷰) | 담당자·기한·다음 일정이 모두 명시적으로 언급된 케이스 (명확한 케이스) | 담당자·기한을 정확히 1개 항목에만 배정, Action Item 개수도 필요한 만큼만(1개) 정확히 산출. "다음 주 월요일"과 "정확한 날짜 미상"을 구분해 표기하는 등 세밀한 정직성 확인 |

## 배포 결과 요약

시스템 프롬프트를 매 대화마다 재입력하지 않아도, 프로젝트 지침만으로 정하윤 페르소나·8항목 형식·안전장치(모르면 모른다고 말하기, 화자 불명 표시)가 새 대화창에서 자동으로 적용됨을 확인했다. 이는 과제에서 요구하는 "재사용 가능한 형태로 배포"라는 목표를 충족한다.

다만 두 테스트를 대조한 결과, **입력 정보의 명확성에 따라 처리 품질에 차이가 있다는 점을 추가로 발견했다.** 정보가 애매한 스크립트(화자 불명, 미합의 안건 포함)에서는 Action Item 담당자·기한 배정이 다소 느슨하게 처리되는 경향이 있었고, 정보가 충분한 스크립트에서는 담당자·기한·Action Item 개수 모두 정확하게 산출됐다. 이는 시스템의 결함이라기보다, "애매함 처리"가 이 시스템에서 가장 난이도가 높은 영역이라는 점을 실증적으로 보여주는 결과로 판단한다. 향후 개선 시, Few-shot 예시 중 애매한 케이스(예시 2)의 비중을 프로젝트 지침에서 더 강조하는 방향을 고려할 수 있다.

이 결과를 v1→v2 검증 당시(동일 스크립트를 동일 대화창 조건에서 2회 반복 실행)와 단순 비교하기는 어렵다. 이번 배포 테스트는 ① 완전히 새로운 대화 세션, ② 참고 파일이 첨부된 프로젝트 환경이라는 점에서 검증 당시와 조건이 다르다. 특히 프로젝트에 스크립트 원본 파일이 함께 첨부되어 있어, 모델이 파일 맥락을 간접적으로 참고했을 가능성을 배제할 수 없다. 따라서 이번 테스트로 "v2가 프로젝트 환경에서는 담당자 처리가 느슨해진다"고 단정하기보다는, "배포 환경(프로젝트, 파일 첨부 여부 등)에 따라 판단의 엄격도가 달라질 수 있다"는 가능성을 발견한 것으로 해석하며, 이는 후속 검증이 필요한 지점으로 남긴다.
